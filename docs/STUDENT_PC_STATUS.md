# 내 PC 상태(CPU·메모리·디스크)와 직전 측정 대비 추이 비교

이 문서는 학생이 작성했습니다. 제공 문서와 제공 코드(`src/`, `public/`, `tools/`, 제공 `docs/`)는 고치지 않았습니다.

## 0. 표기

| 표기 | 뜻 |
|---|---|
| [실제 측정] | 이 PC에서 도구를 실행해 잰 값입니다. |
| [예시] | 설명용 값입니다. 이 PC에서 잰 값이 아니며 저장하지 않습니다. |
| [모의 점검] | 가짜 값으로 함수만 검사한 결과입니다. 이 PC의 실제 값이 아닙니다. |
| [코드 확인] | 소스를 읽고 확인했습니다. 실행하지 않았습니다. |
| [미확인] | 확인하지 못했습니다. 되는 것처럼 읽으면 안 됩니다. |

화면 출력과 설명에서 실제 측정값과 예시 값이 섞이지 않도록, 출력의 **모든 줄 앞에** `[실제 측정]` 또는 `[예시]`를 붙입니다.

## 1. 제공 기능과 내가 만든 부분

| 구분 | 내용 |
|---|---|
| 제공 기능 | 앱에는 CPU·메모리·디스크를 보여 주는 기능이 **없습니다.** 「내 기기」는 운영 측이 판정한 보안 기준 충족 여부(`compliant`/`noncompliant`/`unknown`)이고, 「진단 정보」는 requestId·component·version·engine·ai·checkedAt만 담습니다. 서버 API 16개에도 PC 자원 경로가 없고, 소스에 `node:os`·`fs.statfs` 사용이 없습니다. [코드 확인] |
| 내가 만든 부분 | `student/pc-status.mjs`(측정·비교 도구), `docs/STUDENT_PC_STATUS.md`(이 문서) 두 파일입니다. |
| 앱 화면과의 관계 | 이 도구는 **앱 화면에 나오지 않습니다.** PowerShell에서 실행합니다. 화면에 카드를 넣으려면 제공 파일(`src/server.mjs`, `public/app.js`, `public/index.html`)을 고쳐야 해서 이번에는 하지 않았습니다. |

`ceda9c2`에서는 서버 경로가 이 도구를 불러 화면에 썼으나, 제공 서버를 고치지 않는다는 규칙에 따라 되돌렸습니다. 지금은 위 표대로 앱 화면에 나오지 않습니다.

중복 구현이 아님을 확인한 근거는 위 [코드 확인]이며, 키워드 검색 기준이라 다른 이름의 기능이 있을 가능성은 완전히 배제하지 못했습니다.

## 2. 읽는 값, 방법, 단위

모두 Node.js 내장 기능만 씁니다. 관리자 권한, 외부 프로그램, 네트워크를 쓰지 않습니다.

| 값 | 읽는 방법 | 단위 | 비고 |
|---|---|---|---|
| CPU 사용률 | `os.cpus()`의 누적 시간을 1000 ms 간격으로 두 번 읽어 `(1 − 유휴/전체) × 100` | % | 1초 구간의 평균입니다. 순간 값이라 측정마다 크게 달라질 수 있습니다. |
| 메모리 전체 | `os.totalmem()` | GiB (2³⁰ 바이트) | |
| 메모리 여유 | `os.freemem()` | GiB | 운영체제가 보고한 값입니다. |
| 메모리 사용량 | 전체 − 여유 | GiB | 도구가 계산한 값입니다. |
| 디스크 전체 | `fs.statfsSync(드라이브 루트)`의 `blocks × bsize` | GiB | 기본은 도구를 실행한 폴더가 있는 드라이브입니다. |
| 디스크 남은 공간 | 같은 호출의 `bavail × bsize` | GiB | 일반 사용자가 쓸 수 있는 공간 기준입니다. |
| 측정 시각 | CPU 측정 구간이 끝난 직후 | ISO 8601 UTC와 한국 시각 | 메모리·디스크를 읽은 시각이며, CPU 값은 이 시각에 끝난 1000 ms 구간입니다. |

## 3. 읽지 못한 값 (확인 불가)

예시 값을 읽은 값처럼 채우지 않고 `확인 불가 — 이유: ...`를 보여 줍니다. 이유는 오류 이름이나 코드만 쓰고 경로는 넣지 않습니다.

| 상황 | 표시되는 이유(요지) |
|---|---|
| `os.cpus()`가 빈 목록 | 코어 정보를 주지 않았습니다 |
| CPU 시간이 늘지 않음·줄어듦·코어 수 변화 | 사용률을 계산할 수 없습니다 |
| 메모리 여유가 전체보다 큼 등 이상한 값 | 운영체제가 준 값이 올바르지 않습니다 |
| 디스크 읽기 오류(예: `EPERM`) | 읽지 못했습니다(오류 코드) |
| `fs.statfsSync`가 없는 Node.js | 읽는 기능이 없습니다 |
| `LOCALAPPDATA` 없음 | 기록 폴더를 정할 수 없어 저장과 비교를 하지 않습니다(`--data-dir`로 지정 가능) |

위 항목은 [모의 점검]으로 검사했습니다. 실제 PC에서 이 오류가 일어나는 것을 재현한 것은 아닙니다. [미확인]

## 4. 추이 비교 기능

직전 측정과 이번 측정을 나란히 놓고 변화량과 방향을 보여 줍니다.

- 비교 항목: CPU 사용률(단위 `%p`), 메모리 사용량(GiB), 디스크 남은 공간(GiB).
- 방향 표현: 표시한 자릿수(CPU 0.1, GiB 0.01)로 반올림한 값을 비교해 `증가`/`감소`/`변화 없음(표시 자릿수 기준)`만 말합니다.
- **하지 않는 것:** 상태에 이름을 붙이는 판정은 하지 않습니다. 근거 없는 임계값을 만들지 않았습니다.
- 한쪽이라도 확인 불가이면 그 항목만 `비교 불가 — 이유`를 보여 주고, 나머지는 비교합니다.
- 디스크 경로가 이전과 다르면 비교하지 않습니다. 두 측정의 시각 순서를 확인할 수 없어도 비교하지 않습니다.
- 두 측정 사이의 간격(시간·분·초)을 함께 보여 줍니다.

## 5. 측정 기록 (프로젝트 밖)

- 위치: `%LOCALAPPDATA%\keshev-pc-status\samples.jsonl` (이 PC에서는 `C:\Users\<사용자>\AppData\Local\keshev-pc-status\samples.jsonl`). [실행 확인: 기본 폴더 계산]
- 형식: 한 줄에 측정 하나(JSON). 필드는 `version`, `source`(`measured`), `measuredAt`, `cpu`, `memory`, `disk`입니다. 호스트 이름·사용자 이름·프로세스 목록은 저장하지 않습니다.
- 프로젝트 폴더 안에는 아무것도 쓰지 않으므로 `.gitignore` 변경이 필요 없고 커밋에 섞이지 않습니다. [실행 확인: 실행 후 `git status`에 도구 파일 외 변화 없음]
- 예시 값은 저장하지 않으며, 기록 파일에 `example` 줄이 섞여 있어도 읽을 때 건너뜁니다. [모의 점검]
- 읽을 수 없는 줄은 건너뛰고 개수를 알려 줍니다. 파일이 4 MiB를 넘으면 뒤쪽 4 MiB만 읽습니다. [코드 확인]
- 기록은 지우지 않습니다. 직접 지우려면 위 폴더를 삭제하면 됩니다.

## 6. 같은 결과를 다시 만드는 순서

작업 폴더는 이 브랜치(`pc-status`)를 내려받은 폴더의 최상위입니다(`student\pc-status.mjs`가 보이는 폴더). Node.js 24.19.0이 필요하고 `npm install`은 필요 없습니다.

```powershell
# 1) 도구가 있는 폴더에서 PowerShell을 연 뒤, 문법과 모의 점검
node --check student\pc-status.mjs
node student\pc-status.mjs --self-test

# 2) 설명용 예시 값 (실제 값이 아님, 저장하지 않음)
node student\pc-status.mjs --example

# 3) 실제 측정. 첫 실행은 비교할 이전 기록이 없어 "처음 측정"이라고 나옵니다.
node student\pc-status.mjs

# 4) 몇 분 뒤 한 번 더 측정하면 직전 측정과 비교합니다.
node student\pc-status.mjs

# 5) 측정하지 않고 저장된 마지막 두 기록만 다시 비교
node student\pc-status.mjs --compare
```

연습용 기록 폴더로 내 실제 기록을 건드리지 않고 시험하려면 `--data-dir <빈 폴더 경로>`를 붙입니다. 같은 폴더를 모든 명령에 써야 이전 기록과 비교됩니다.

### 확인 순서와 예상 결과

| 순서 | 할 일 | 예상 결과 |
|---|---|---|
| 1 | `node --check student\pc-status.mjs` | 아무것도 출력하지 않고 끝납니다. |
| 2 | `--self-test` | `[모의 점검] 합계: 통과 19, 실패 0`. 모든 줄이 `[모의 점검]`으로 시작합니다. |
| 3 | `--example` | 모든 줄이 `[예시]`로 시작하고, 마지막에 디스크가 `확인 불가` 예시로 나옵니다. |
| 4 | 인수 없이 실행 | 모든 줄이 `[실제 측정]`으로 시작합니다. 값마다 단위(`%`, `GiB`)가 있고, 처음이면 비교 대신 "처음 측정" 안내가 나옵니다. |

## 8. 한계

- 앱 화면에는 나오지 않고 PowerShell 도구로만 씁니다.
- 한 PC의 값만 읽습니다. 다른 PC나 서버 값은 읽지 않습니다.
- 프로세스별 사용량, 온도, 네트워크, 여러 드라이브 동시 비교는 하지 않습니다.
- 기록은 이 PC의 사용자 계정 폴더에만 있으며 백업하지 않습니다. 필요하면 위 폴더를 직접 복사하세요. 비밀값은 들어 있지 않습니다.
