# 완성본 시연 순서와 정리 (케셰브 · 신영한)

제출한 커밋은 `ceda9c2`이고, 재제출은 하지 않았습니다.

이 문서는 만든 기능을 한 번에 보여 주기 위한 정리입니다. 상세 설명은 `docs/RUN_GUIDE.md`(실행 안내)와 `docs/STUDENT_DASHBOARD.md`(대시보드)를 보세요. 이 문서는 새 코드나 다른 문서를 바꾸지 않습니다.

- 화면 틀: 관제 대시보드형(맨 위 상태 카드 4개, 아래 추이와 기록)
- 실행 형태: 포장 없이 내 PC에서 실행. 포장 명령(`npm run package-app`)은 실행하지 않았습니다.
- 작업 폴더 `on-client-pcstatus`, 이 문서의 브랜치 `pc-status-compliant`(`pc-status`의 `ceda9c2`에서 갈라져 나옴). `master`(`37995f6`)와 `pc-status`는 건드리지 않았습니다.
- **이 버전의 가장 큰 차이:** `ceda9c2`에는 제공 서버 `src/server.mjs`를 12줄 고친 수정(라우트 `/api/pc-snapshot`)이 들어 있었습니다. 포털 안내문에 「제공 서버는 고치지 않는다」가 있어 이 브랜치에서 되돌렸습니다(`8aa8c70`). 그래서 이 버전은 **제공 서버를 고치지 않아 화면 실측은 연결하지 않았습니다.** 실측 기능은 `ceda9c2` 커밋에 있었습니다.
- 이 문서가 기준으로 삼은 마지막 커밋은 `ecb7a55`입니다. 이 문서를 추가하는 커밋은 포함하지 않습니다.

## 2. 핵심 기능 3가지와 시연 순서

| 번호 | 핵심 기능 | 이 버전에서 |
|---|---|---|
| ① | PC 상태 실측(CPU·메모리·디스크) | 명령줄 `node student\pc-status.mjs`. 화면 연결 안 함 |
| ② | 네트워크·방화벽·Windows 기록(System·Application 경고·오류) 건수 읽기 | 명령줄 `node student\pc-security-status.mjs`. 읽기 전용, 못 읽으면 `확인 불가`. 화면 연결 안 함 |
| ③ | 다시 조회와 오류 화면 | 화면에서 시연 가능. 실패 이유는 "경로 연결 안 함(HTTP 404)" |

### 준비

1. PowerShell에서 작업 폴더 `<내 PC의 작업 폴더>\on-client-pcstatus`로 이동합니다.
2. ③을 화면으로 보여 줄 때만: 이미 켜 둔 서버가 있으면 끄고(방법은 `docs/RUN_GUIDE.md` 6장), `.\tools\start-alekov.ps1`로 켠 뒤(또는 `npm start`) Chrome에서 `http://127.0.0.1:5189/`를 열어 「보호 현황」 탭을 엽니다. 켜 둔 서버를 새 코드로 다시 켜야 이 버전의 화면이 나옵니다.

시작 도구로 켜기와 `npm start` 모두 [직접 확인]. 이 시연에서 화면과 출력의 숫자는 모두 `[예시 값]`으로 적었습니다.

## 5. 한계

### 5-1. 약속한 한계

- 이 앱은 완성된 보안 제품이 아니라, 내 PC 상태를 읽어서 숫자와 변화를 보여 주는 학습용 모니터링 앱입니다. 침해나 공격을 탐지하거나 막지 않습니다.
- **이 버전은 제공 서버를 고치지 않아 화면 실측은 연결하지 않았습니다.** 카드·한 줄 요약·상세는 항상 `확인 불가`이고, 값은 명령줄 도구로만 확인합니다. 실측 기능은 `ceda9c2` 커밋에 있었습니다. 제출한 `ceda9c2`에는 제공 파일 `src/server.mjs`를 12줄 수정한 내용(라우트 `/api/pc-snapshot` 1개)이 들어 있고, 이 브랜치는 그것을 되돌린 버전이며 재제출하지 않았습니다.
- 연결하면 쓰일 코드(상세 패널, 카드, 저장 기록)의 범위 검증 기준이 세 곳에서 다릅니다. 이 버전에서는 값이 오지 않아 드러나지 않습니다.
- **SDP 서버는 실제로 연결되지 않습니다**(발급 인증서 없음). 화면의 SDP 칸은 `SDP 미연결`로 표시되고, 조회가 실패했을 때는 `확인 불가`로 씁니다. 조회 중에 SDP 서버에 접속하지 않습니다. [소스 확인] 화면 표시는 [AI 확인]. `ceda9c2`에서는 [직접 확인, ceda9c2 기준]
- **`student/appearance.json`은 이 시작 틀(0.2.11)에 읽는 코드가 없어 쓰지 않았습니다.** 파일도 없고 `src`·`student`·`public`에서 읽는 코드를 찾지 못했습니다. [AI 확인]
- **메모리·디스크·방화벽의 이전 조회 값은 저장되지만 화면에서는 보이지 않습니다.** 화면의 그래프는 CPU 사용률만 그립니다. 이 버전에서는 새 값이 저장되지 않으므로 그래프에 보이는 막대는 이전 버전에서 저장된 기록뿐입니다. [소스 확인] / [AI 확인]
- **포털 예시의 세 단계 상태 판정(상태 이름을 붙여 나누는 방식)은 근거 없는 임계값이라 따라 하지 않았습니다.** 화면에는 숫자와 변화(▲ ▼ =), `켜짐/꺼짐`만 보여 줍니다. 판정 단어와 상태에 따라 바뀌는 색이 없는지 모의 점검으로 확인했습니다. [AI 확인]
- **오류·경고 건수는 침해나 공격 탐지 결과가 아닙니다.**
- 기록은 이 브라우저의 `localStorage`에만 숫자로 저장되고(최대 10개) 서버나 외부로 보내지 않습니다. 주소·포트별로 따로 저장되어 포트를 바꾸면 보이지 않을 수 있습니다. [소스 확인]
- Windows PowerShell을 쓰는 읽기 도구라 Windows 밖에서는 동작하지 않을 수 있습니다. [미확인]
- 막대 높이는 5% 단위로 반올림해 그립니다. 정확한 값은 막대 아래 숫자입니다. [소스 확인]

### 5-3. 이 버전에서 [미확인]으로 돌린 항목 (`ceda9c2` 기준으로는 [직접 확인])

사용자가 `ceda9c2` 화면을 새로고침한 뒤 직접 확인해 모두 문제 없이 동작했던 항목입니다. 이 버전은 화면 동작이 달라서(값이 없고 실패 이유가 다름) 같은 확인을 이 버전에서 다시 하기 전까지 [미확인]입니다. 사용자가 이 버전에서 직접 눌러 본 것만 나중에 `[직접 확인]`으로 올립니다.

- 조회와 다시 조회, 카드 4개 값, 한 줄 상태 표시 (이 버전은 값이 없음)
- CPU 막대 그래프(숫자 표시, 마우스 올리기, `직전보다 ▲/▼` 한 줄) (이 버전은 새 점이 안 생김)
- 한 줄 요약(네트워크, Windows 기록 건수, 침해나 공격 탐지 결과가 아니라는 문구, `SDP 미연결`) (이 버전은 요약이 `확인 불가`, `SDP 미연결`만 남음)
- 「자세히」 열기
- 새로고침 후 기록 유지
- Tab·Enter로 조회(키보드)
- 「기록 지우기」
- 서버를 끈 상태의 실패 화면(확인 후 서버를 다시 켬) (이 버전은 서버를 켜 둬도 실패 화면이 나옴)

이 버전에서도 그대로 유효한 [직접 확인]: `npm start`로 켜도 사이트가 열림, 안내서만 보고 서버 켜기·접속·끄는 법(`-Background` 종료 포함), 서버를 켠 창에서 Ctrl+C로 끄기, 2·3일차 점검 도구(명령줄) 실행 결과.
