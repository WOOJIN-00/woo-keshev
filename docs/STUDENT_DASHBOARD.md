# 4일차: 화면 정리 — 핵심 3가지 패널, 다시 조회와 대기 표시, 실패 시 오류 화면

이 문서는 학생이 작성했습니다. 이 브랜치(`pc-status`)에서 **제공 파일은 `src/server.mjs` 하나만, 라우트 1개를 추가하는 방식으로 수정했습니다**(3장). `public/`과 다른 제공 파일은 수정하지 않았습니다.

## 0. 표기와 실행 주체

| 표기 | 뜻 |
|---|---|
| [실제 측정] | 이 PC에서 읽은 값입니다. 화면의 값 줄 앞에 붙는 표시이기도 합니다. |
| [예시] | 설명용 값입니다. **이 화면에는 예시 값이 나오지 않습니다.** 설명서와 `--example` 출력에서만 씁니다. |
| [모의 점검] | 가짜 DOM과 가짜 `fetch`로 함수만 검사한 결과입니다. 실제 브라우저 화면이 아닙니다. |
| [실행 확인] | 실제로 실행해 출력이나 응답을 확인했습니다. |
| [코드 확인] | 소스를 읽고 확인했습니다. 실행하지 않았습니다. |
| [미확인] | 확인하지 못했습니다. 되는 것처럼 읽으면 안 됩니다. |

**실행 주체:** [실행 확인]과 [모의 점검] 항목은 학생의 PC에서 수업용 AI(Claude Code)가 실행하고 출력을 확인한 것입니다. 학생이 브라우저에서 직접 확인한 결과는 이 문서를 쓴 시점에 [미확인]입니다.

## 1. 요청과 핵심 3가지

| 번호 | 핵심 기능 | 화면에서 하는 일 |
|---|---|---|
| ① | PC 상태 실측(2일차) | CPU 사용률(%), 메모리·디스크(GiB)를 측정 시각과 함께 `[실제 측정]`으로 표시 |
| ② | 네트워크·방화벽·Windows 기록 읽기(3일차) | 네트워크 요약, 방화벽 켜짐 여부(읽기만 함), System·Application 오류·경고 건수와 "침해나 공격 탐지 결과가 아닙니다" 안내. 앱의 SDP 연결 상태는 **별도 구역**으로 분리 |
| ③ | 다시 조회와 오류 화면 | 「PC 상태 조회」/「다시 조회」 버튼(카드 바로 위 한 곳), `조회 중` 표시, 실패 시 항목별 이유와 다음에 할 일 |

## 2. 화면에서 달라진 점

- **위치:** 앱의 「보호 현황」 탭(기본 탭)에서 첫 학생 칸인 「학생 구현 표시 · renderIdentity」 카드의 맨 위에 관제 대시보드(10장)가 있고, 그 바로 아래에 이 「핵심 3가지」 패널이 있습니다. 그 아래의 내 계정·기기 목록·세션 목록 표시는 그대로입니다. 「PC 상태 조회」 버튼은 화면에 **한 곳**뿐이며 패널이 아니라 대시보드의 카드 바로 위에 있습니다(10장). [모의 점검, 실행 확인]
- **처음 상태:** `조회 전`입니다. 버튼을 누르기 전에는 서버에 아무 요청도 보내지 않습니다(자동 조회 없음). [모의 점검]
- **대기 표시:** 조회하면 `조회 중` 글자가 나오고 버튼 글자가 「조회 중…」으로 바뀝니다. 이때 이전 결과는 지워져 현재 결과처럼 남지 않습니다. 조회 중에 버튼을 연타해도 요청은 한 번만 나갑니다. [모의 점검, 실행 확인]
- **결과 상태 글자:** 버튼 옆 한 줄에 시각과 함께 `14:02 조회 성공`, `일부 확인 불가`, `실패`처럼 글자로 보여 줍니다(10-3). 색이 아니라 글자로 구분합니다.
- **키보드:** 버튼은 일반 `button` 요소(type=button)라서 Tab으로 이동하고 Enter·Space로 누릅니다. 조회 중에는 비활성화 대신 `aria-disabled`·`aria-busy`를 써서 초점이 버튼에 남고, 화면이 다시 그려져도 초점을 새 버튼으로 되돌립니다. [모의 점검] 실제 브라우저와 보조 기술에서의 동작은 [미확인]입니다.
- **화면에 쓴 것:** `createElement`와 `textContent`만 씁니다. `innerHTML`, 인라인 `style`, `eval`은 쓰지 않았고, 스타일은 새 스타일시트 한 개로만 넣습니다(10-8). [코드 확인]
- **`student/appearance.json`은 만들지 않았습니다.** 이 시작 틀(0.2.11)의 코드와 문서 어디에도 이 파일을 읽는 곳이 없어 만들어도 효과가 없고 형식도 알 수 없습니다. [코드 확인]

## 3. 제공 파일 수정, 라우트 1개

| 항목 | 내용 |
|---|---|
| 수정한 제공 파일 | **`src/server.mjs` 1개** (12줄 추가, 삭제 0줄) |
| 추가한 것 | `GET /api/pc-snapshot` **라우트 1개**와 조회 중 표시 변수 1개 |
| 이유 | 브라우저는 PC의 CPU·네트워크·방화벽·Windows 기록을 직접 읽을 수 없고, 제공 서버에는 이 값을 주는 경로가 없었습니다. 학생 영역(`student/extension.mjs`)만으로는 값을 얻을 수 없습니다. [코드 확인] |
| 하는 일 | `student/pc-status.mjs`의 `measureSample`과 `student/pc-security-status.mjs`의 `collectPc`를 호출해 결과를 돌려줍니다. SDP 상태는 포함하지 않습니다(화면이 기존 `/api/diagnostics`를 따로 읽음). |
| 수정하지 않은 것 | `public/`(index.html, app.js, style.css 등), 다른 라우트, 인증·판정 코드, 나머지 모든 제공 파일 |
| 커밋 | 이 수정만 담은 별도 커밋입니다. (제목: "제공 파일 수정, 라우트 1개: GET /api/pc-snapshot 추가 (src/server.mjs)") |

`main`과 이미 낸 제출물에는 이 수정이 없습니다. 이 수정은 `pc-status` 브랜치의 개발 복사본에만 있습니다.

**설치형 앱에 반영된다고 가정하지 않습니다.** 설치형 앱이 무엇을 반영하는지는 이 저장소에서 확인할 수 없습니다(설치 도구 `tools/install.mjs`가 이 저장소에 없음). 그 앱의 서버에 이 라우트가 없으면 패널은 값을 만들어 내지 않고 `확인 불가`와 이유, 다음에 할 일을 보여 줍니다(5장). [코드 확인, 모의 점검, 실행 확인]

## 4. 새 라우트의 안전 점검 결과

수정한 서버를 임시 포트에 켜고 실제로 시험했습니다. 사용자가 켜 둔 앱은 건드리지 않았습니다. 한국 시각 2026-10-28 16시 20분대입니다.

| 확인 요청 | 결과 | 근거 |
|---|---|---|
| 127.0.0.1에서만 열리는가 | 예. 서버가 듣는 주소는 `127.0.0.1` 하나이고 `0.0.0.0`·`::`로 열려 있지 않음. 이 PC의 다른 IPv4 주소 2개로 접속을 시도했으나 연결 성공 0개. Host 이름이 `evil.example`이거나 IP로 바뀌면 `403 HOST_REJECTED`, `Host: localhost`는 허용 | [실행 확인] |
| CORS 허용이 없는가 | 예. 서버 소스에 `access-control` 헤더 설정이 없고, 다른 `Origin`을 붙인 요청과 사전 요청(OPTIONS)의 응답에도 `access-control-*` 헤더가 없음. `Sec-Fetch-Site: cross-site` 요청은 `403 ORIGIN_REJECTED` | [코드 확인] [실행 확인] |
| 연타해도 PowerShell이 여러 개 안 뜨는가 | 예. 8개를 동시에 요청했을 때 동시에 떠 있던 PowerShell은 최대 1개였고 8개 응답이 같은 측정 시각을 공유함. 연타가 끝난 뒤 새로 요청하면 다른 측정 시각의 새 조회가 실행되어 「다시 조회」는 정상 동작 | [실행 확인] |
| 읽기 전용 허용 목록을 그대로 거치는가 | 예. 서버가 호출하는 `collectPc`는 PowerShell을 띄우기 전에 허용 목록 검사를 합니다. 요청 중 실제로 실행된 PowerShell 명령을 가져와 검사한 결과 허용 목록 검사를 통과했고 도구의 `buildScript(24)`와 글자 그대로 같았음. 쓰인 명령은 `Get-NetAdapter`, `Get-NetConnectionProfile`, `Get-NetFirewallProfile`, `Get-WinEvent`, `Get-Date`, `Select-Object`, `ConvertTo-Json`뿐. 변경 명령은 공개된 실행기에서도 거절됨 | [실행 확인] [모의 점검] |

그 밖에 확인한 것:

- 쿼리(`?hours=1` 등)는 `400 QUERY_REJECTED`로 거절됩니다. 이 경로는 사용자 입력을 받지 않습니다. [실행 확인]
- POST는 `404 NOT_FOUND`입니다. GET 전용입니다. [실행 확인]
- 학생 도구 파일이 없는 앱 버전에서는 `501 PC_SNAPSHOT_UNSUPPORTED`로 답하도록 만들었지만, 이 상황을 실제로 재현하지는 않았습니다. [코드 확인] [미확인]
- 서버에서 PowerShell 대기 시간은 8초로 제한됩니다(서버의 처리 제한 15초보다 짧음). [코드 확인]

## 5. 실패했을 때의 오류 화면

조회에 실패하면 **예시 값이나 이전 결과로 채우지 않습니다.** 값 줄은 나오지 않고, 「조회하지 못한 항목과 다음에 할 일」 목록에 항목별 이유와 할 일이 나옵니다. SDP 상태는 PC 조회와 별개라 따로 판정합니다.

| 상황 | 화면의 상태 글자와 이유 | 다음에 할 일 |
|---|---|---|
| 앱 서버에 PC 조회 경로가 없음(404/501) | `조회 실패`, "이 앱 서버에는 PC 조회 경로가 없습니다(HTTP 404)" | 개발 복사본이면 앱을 껐다가 다시 켜세요(서버는 켤 때만 코드를 읽음). 설치형 앱이면 이 기능이 없는 버전일 수 있으니 PowerShell 도구로 확인 |
| 주소 거절(403) | `조회 실패`, "앱 서버가 이 주소에서 온 요청을 거절했습니다" | 주소창이 `http://127.0.0.1:포트/` 또는 `http://localhost:포트/`인지 확인 |
| 서버에 연결할 수 없음·12초 안에 응답 없음 | `조회 실패`, 이유에 "연결하지 못했습니다" 또는 "12초 안에 응답이 없습니다". SDP는 `확인 불가`이며 **미연결로 쓰지 않음** | 앱 서버가 켜져 있는지 확인한 뒤 「다시 조회」 |
| 서버 오류(503 등)·응답 형식 이상 | `조회 실패`, HTTP 상태와 코드 또는 "형식이 예상과 달라 표시하지 않습니다" | 잠시 뒤 「다시 조회」, 계속되면 PowerShell에서 `node student\pc-security-status.mjs` |
| 일부 항목만 읽지 못함 | `일부 확인 불가`. 읽은 값은 그대로 표시하고 읽지 못한 항목만 목록에 나옴 | 이유에 접근 거부가 있으면 "관리자 권한이 필요한 항목일 수 있습니다. 바꾸려 하지 않았으니 담당자에게 확인", 그 외에는 잠시 뒤 「다시 조회」 |

위 상황은 모두 [모의 점검]으로 검사했습니다. 이 중 "경로가 없음(404)"은 이전 코드로 떠 있던 실제 서버(5189)의 실제 응답으로도 확인했습니다(가짜 DOM에서 그림). [실행 확인]

## 6. 실제 측정과 예시 값의 구분

- 화면(패널)에는 예시 값이 없습니다. 값이 있는 줄은 모두 `[실제 측정]`입니다. 처음(`조회 전`)과 실패 화면에는 값 줄이 없습니다. [모의 점검]
- 예시 값은 CLI 도구의 `--example` 출력과 이 설명서에서만 쓰며 줄마다 `[예시]`가 붙습니다.
- SDP `예제 모드`(앱을 `-Demo`로 켠 경우)는 "실제 SDP가 아닙니다"라고 표시합니다. [모의 점검]

## 9. 한계

- 패널은 「보호 현황」의 한 칸 안에 들어갑니다. 화면 전체 배치(탭·카드 순서)는 제공 파일(`public/index.html`)의 몫이라 바꾸지 않았습니다.
- 조회 기록은 이 브라우저의 `localStorage`에 보관합니다(10장). **기록은 주소·포트별로 따로 저장되어, 포트가 바뀌거나 다른 폴더의 앱을 켜면 안 보일 수 있습니다.**
- 기록은 이 브라우저 안에만 있습니다. 다른 브라우저, 다른 PC, 브라우저 데이터를 지운 뒤에는 보이지 않으며, 2일차 CLI 도구의 기록 파일(`%LOCALAPPDATA%\keshev-pc-status`)과는 별개입니다. 백업하지 않습니다.
- 카드는 이번 방문에서 조회한 결과만 보여 줍니다. 새로고침하면 카드는 `조회 전`으로 돌아가고 저장된 기록으로 그린 CPU 막대 그래프만 남습니다.
- 조회는 약 3~5초 걸리고, 자동으로 다시 조회하지 않습니다.
- Windows 기록은 System·Application의 오류·경고 건수만 셉니다.
- IP·MAC 주소, 무선 이름(SSID), 기록 메시지 본문은 읽거나 표시하지 않습니다.
- 우리 칸은 2열 격자의 오른쪽 절반이라 폭이 약 321~619px로 정해져 있고(10-8), 제공 `body`의 최소 너비 1024px 때문에 창이 그보다 좁으면 페이지 전체에 가로 스크롤이 생깁니다. 이 둘은 제공 파일의 몫이라 이번에는 고치지 않았습니다.
- 그래프는 **CPU 사용률만** 그립니다. 메모리·디스크·방화벽의 이전 조회 값은 저장되지만 화면에서는 볼 수 없습니다(10-7). 막대 높이는 5% 단위로 반올림해 그렸고 정확한 값은 막대 아래 숫자입니다.
- 한 줄 요약의 Windows 오류·경고 건수는 System·Application의 합계이고 이번 방문에서 조회한 결과만 보여 줍니다(저장하지 않음).

### 10-3. 버튼과 상태 줄

- 「PC 상태 조회」(조회 후에는 「다시 조회」) 버튼은 **카드 위에 한 곳만** 있습니다. 코드에서 버튼을 만드는 곳이 한 군데이고, 조회 중 연타해도 요청은 한 번입니다.
- 버튼 옆은 **한 줄**입니다.
  - 조회 전: `조회 전`(저장된 기록이 있으면 ` · 저장된 마지막 조회 10/28 16:09`)
  - 조회 중: `조회 중…`
  - 조회 뒤: `14:02 조회 성공`. 이번 방문의 두 번째 조회부터 `14:02 다시 조회 성공`입니다. 결과 글자는 `성공` / `일부 확인 불가` / `실패`입니다. 시각은 한국 시각이고 카드·그래프와 같은 시각입니다. 색이 아니라 글자로 구분하며 `role="status"`입니다.
- 「핵심 3가지」 패널에는 조회 위치를 알리는 한 줄만 있고 버튼과 상태 줄은 없습니다.

### 10-4. 상태 카드 (CPU 사용률·메모리·디스크·방화벽)

| 카드 | 값 있음 | 규칙 |
|---|---|---|
| CPU 사용률 | `12.5 %` | 1초 구간의 순간 값 |
| 메모리 | `54.6 % 사용(계산값)` | 사용률 = (전체 − 여유) ÷ 전체 × 100. 읽은 전체·여유 바이트로 계산한 값이며 **「자세히」에 계산 방법을 적음** |
| 디스크 | `106.86 GiB 남음` | 남은 공간 |
| 방화벽 | `모두 켜짐`, `모두 꺼짐` | 프로필이 **둘 이상이고 모두 같은 켜짐 또는 꺼짐일 때만** 줄입니다. 아래에 `프로필 3개: Domain · Private · Public`을 작게 보여 줍니다 |
| 방화벽(다를 때) | `Domain 켜짐 · Private 켜짐 · Public 꺼짐` | 하나라도 다르면 프로필별 글자. 프로필이 1개이거나 모두 `설정 안 됨`이어도 줄이지 않고 프로필별로 보여 줌 |

- 값은 크게, 제목은 작게 두고, 측정 시각(작은 글씨 `10/28 14:02 측정`)과 제목 옆 작은 `[실제 측정]`을 붙입니다.
- 조회 전에는 `조회 전`, 조회 중에는 `조회 중`만 보입니다.
- 읽지 못한 카드는 큰 글씨 `확인 불가`와 짧은 이유 한 줄이고 `[실제 측정]`과 값은 없습니다. 확인 불가 카드가 있으면 카드 아래에 한 번만 "이유와 다음에 할 일은 아래 패널의 「조회하지 못한 항목과 다음에 할 일」에 있습니다"라고 알립니다. 다음에 할 일 목록 자체는 패널에 그대로 있습니다.

### 10-5. CPU 막대 그래프

- **데이터:** 저장된 기록(`localStorage`, 형식 그대로)의 `cpu` 값을 오래된 것부터 **왼쪽에서 오른쪽으로 최대 10개** 그립니다. 이미 쌓인 기록이 그대로 쓰이며, 이번 방문에서 조회하기 전에도 새로고침하면 저장된 기록으로 그려집니다.
- **숫자가 항상 보임:** 막대 아래에 값(`12.1`, `100.0`)이 항상 나옵니다. 마우스를 올리면 `10/28 14:02 CPU 12.1 %`(`title`)가 나오고, 화면 읽기 도구는 막대마다 같은 문장을 읽습니다(`aria-label`). 가장 최근 막대의 숫자는 굵게 합니다. **색으로만 구분하지 않습니다.** 막대는 한 가지 중립색이고, 기본 `<meter>` 요소는 값에 따라 초록·노랑·빨강으로 칠해 판정처럼 보일 수 있어 쓰지 않았습니다.
- **높이는 5% 단위로 반올림:** 막대 높이는 0~100%를 5% 단위(`kd-h0`~`kd-h20`)로 반올림해 그립니다. 예: 12.5 % → 3칸(15%), 2.4 % 이하 → 최소선 2px, 97.5 % 이상 → 꽉 참. 그림은 대략이고 **정확한 값은 막대 아래 숫자**입니다. 높이는 0~100% 기준이라 CPU가 10% 안팎이면 막대가 낮게 보입니다.
- **한 줄 변화:** 가장 최근 두 막대를 비교해 `직전보다 ▲ +9.5 %p 증가`, `직전보다 ▼ −10.0 %p 감소`, `직전보다 = 변화 없음`을 보여 줍니다. 읽기에 실패한 조회는 건너뛰므로 "직전"은 직전의 **읽기에 성공한 조회**입니다. 방향은 표시한 자릿수(0.1) 기준입니다.
- **값이 없거나 하나뿐이면:** 막대 없이 "비교할 이전 조회가 없습니다."라고 말합니다.
- **CPU 값을 읽지 못한 조회**(실패 기록)는 그래프에서 빼고 "CPU 값을 읽지 못한 조회 N개는 그래프에서 뺐습니다."라고 알립니다.
- 그래프 아래 한 줄에 왼쪽·오른쪽 시각, 오래된 조회 → 최근 조회, 숫자는 CPU 사용률(%)이고 높이는 5% 단위라는 설명을 넣었습니다.

### 10-6. 네트워크·Windows 기록 한 줄 요약과 SDP

- 한 줄: `[실제 측정] 네트워크 물리 1개 연결됨 · Windows 오류 5·경고 11(최근 24시간)`
  - 네트워크: 가상 어댑터를 뺀 **연결됨** 상태의 물리 어댑터 수입니다. 읽지 못하면 `네트워크 확인 불가`.
  - Windows 기록: System과 Application 두 기록의 **합계**입니다. 한 기록이라도 읽지 못했으면 일부만 더하지 않고 그 수준을 `확인 불가`로 씁니다. 조회 상한(1000건)에 닿은 기록이 있으면 합계 뒤에 `이상`을 붙입니다. 읽지 못하면 `Windows 기록 확인 불가`.
  - 이번 방문에서 조회한 결과만 보여 줍니다(저장하지 않음). 조회 전 `조회 전`, 조회 실패 시 `확인 불가`와 패널 안내.
- 따로 한 줄씩: `이 건수는 침해나 공격 탐지 결과가 아닙니다.`
- 따로 한 줄: SDP 상태. `SDP 미연결` / `SDP 예제 모드(실제 SDP 아님)` / `SDP 연결 설정됨(…실제 응답 성공 확인은 아님)` / `SDP 상태 확인 불가('미연결'이 아닙니다)`. 읽은 상태에는 `[실제 측정]`이 붙고, 확인 불가에는 붙이지 않습니다. 앱은 SDP에 실제로 연결하지 않으며, PC 조회 결과와 SDP 상태는 합치지 않습니다.

### 10-7. 접는 「자세히」와 기록 보관

`<details>` **한 곳**(요약 글자 「자세히」)에 다음을 모았습니다. 열어 둔 상태는 다시 그려져도 유지됩니다.

1. **어댑터별 상태:** `이더넷 — 연결됨 · 물리 유선` 같은 이름·상태·종류, 연결 범주. IP·MAC 주소와 무선 이름(SSID)은 읽거나 표시하지 않습니다.
2. **방화벽 프로필별 설정:** 켜짐 여부와 `들어오는 기본 동작`·`나가는 기본 동작`(허용/차단/설정 안 됨). 기본 동작이 `설정 안 됨`이면 실제 적용값이 아니라는 설명.
3. **Windows 기록 건수(최근 24시간):** System·Application 각각의 오류·경고 건수와 "침해나 공격 탐지 결과가 아닙니다".
4. **보관 위치 · 한계 · 읽는 방식** (아래 한계 문장 포함)
5. 「기록 지우기」 버튼

> 기록은 주소·포트별로 따로 저장되어, 포트가 바뀌거나 다른 폴더의 앱을 켜면 안 보일 수 있습니다.

### 10-8. 스타일 방법과 한계

이 앱은 보안 정책(CSP)으로 `style-src 'self'`를 씁니다. 같은 정책 아래에서 실제 Chrome으로 시험한 결과입니다(이전 화면 정리 때 확인).

| 방법 | 결과 |
|---|---|
| 인라인 `style` 속성 | 차단됨 |
| `<style>` 요소 삽입 | 차단됨 |
| **새 스타일시트(`adoptedStyleSheets`)** | **됨** — 채택. 클래스 규칙·`@container` 사용 가능 |
| 제공 클래스(`.card`, `.btn` 등)와 CSS 변수(`--text`, `--muted`, `--border`, `--surface`, `--bg`, `--radius`) | 사용 가능 |

- **막대 높이:** 제공 스타일에는 막대가 없어 전용 스타일시트가 필요했습니다. 인라인 `style`을 쓸 수 없으므로 높이는 **5% 단위 클래스 21개**(`.kd-h0{height:2px}`, `.kd-h1{height:5%}` … `.kd-h20{height:100%}`)를 스타일시트에 미리 두고 값에 맞는 클래스를 붙입니다. 그래서 `<style>` 요소와 인라인 `style` 속성은 0개입니다.
- **붙이지 못하면:** 스타일시트가 막히거나 지원되지 않아도 오류 없이 숫자와 동작은 그대로이고 막대와 모양만 사라집니다(막대 아래 숫자는 남음). [모의 점검]
- **칸 폭:** 우리 칸은 2열 격자의 오른쪽 절반이라 폭이 정해져 있습니다(1920px 창에서 실측 619px, 1280px·1024px 창은 계산값 약 449px·321px). 카드는 칸 폭 380px 미만에서 1열, 이상에서 2열입니다. 칸 폭 확대는 `public/` 수정이 필요해 범위 밖입니다. 제공 `body { min-width: 1024px }` 때문에 창이 1024px보다 좁으면 페이지 전체에 가로 스크롤이 생기며 이것은 고칠 수 없습니다.
