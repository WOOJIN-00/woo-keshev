# 22단계 새 환경 재현 기록과 버전 기록

이 문서는 학생이 작성한 재현 기록입니다. 서버가 새 환경에서 코드를 실행했다는 뜻이 아니며, AI의 원문 검토 통과는 실행 성공의 증명이 아닙니다. 제공 문서와 제공 코드는 고치지 않았습니다.

## 0. 표기와 실행 주체

| 표기 | 뜻 |
|---|---|
| [실행 확인] | 새 폴더에서 실제로 실행하고 출력이나 응답을 확인했습니다. |
| [모의] | 가짜 DOM과 모의 입력으로 학생 함수만 호출했습니다. 브라우저 화면이 아닙니다. |

**제출본과 재현 커밋의 관계:** 제출하는 최종 커밋은 위 재현 커밋에 이 문서(`docs/STUDENT_REPRODUCTION_22.md`) 한 파일만 추가한 커밋입니다. 문서가 커밋 해시를 바꾸기 때문에 최종 커밋의 해시는 이 문서 안에 적을 수 없습니다. 두 커밋 사이에 이 문서 말고는 차이가 없음은 아래 명령으로 대조합니다.

```powershell
git diff --stat c974014ddd79116a24b5fae9f7300ffbdf002dd7 <제출할 40자리 커밋>
```

이 명령의 결과가 `docs/STUDENT_REPRODUCTION_22.md | ... 1 file changed`이면 코드는 재현한 것과 같습니다. 다른 파일이 보이면 이 문서의 재현 결과를 제출본에 적용할 수 없습니다. 결과는 제출 전에 대화에서 따로 확인합니다.

재현 결과는 모두 위 재현 커밋 하나를 기준으로 합니다. 이전 단계 커밋(예: 20단계 `b856d32`, 21단계 `2cabe79`)에서 따로 얻은 점검 결과는 합치지 않았습니다. 이전 커밋 대비 이번 재현 커밋의 변경은 `docs/STUDENT_RUNBOOK.md`의 절대경로 한 줄을 지운 것뿐입니다. [코드 확인]

## 6. 이동 가능한 구성

다른 환경으로 옮길 때 필요한 것과 하지 않아도 되는 것입니다.

- **옮길 것:** Git이 추적하는 파일 59개(`git ls-files`)가 전부입니다. [실행 확인] 앱 폴더(`on-client`)는 `package.json`과 `src\server.mjs`가 있는 폴더입니다.
- **설치:** 외부 npm 패키지가 없어 `npm install`이 필요 없습니다. Node.js 24.19.0만 있으면 됩니다. [실행 확인: `node_modules` 없이 실행됨]
- **설정 예시:** `.env.example`에는 `ON_PORT`, `ON_ENGINE_ADAPTER`, `ON_AI_MODEL`, `ON_PROJECT_DIRECTORY`, `ON_APPROVED_PUBLIC_PACKAGES` 항목이 있고 비밀값은 없습니다. 서버와 실행 도구의 소스에는 `.env` 파일을 읽는 코드가 없고, 서버는 `ON_PORT`, `ON_ENGINE_ADAPTER`, `ON_APPROVED_PUBLIC_PACKAGES`, `ON_PROJECT_DIRECTORY`를 프로세스 환경변수에서 읽습니다. 실행 도구는 `ON_PORT`만 설정하며, 이름이 `ON_AI_`로 시작하거나 토큰·비밀번호처럼 보이는 환경변수는 서버에 넘기지 않습니다. [코드 확인] 기본 실행은 이 설정 없이 켜졌습니다. [실행 확인]
- **실행 진입점:** `tools\start-alekov.ps1`(포트 기본 5189, `-Port`·`-Demo`·`-Background` 옵션)과 `package.json`의 `start`·`demo`·`check`. 앞 단계 문서의 설명과 일치합니다. [코드 확인]

## 7. 데이터 보존 계획

### 7-1. 무엇이 학생 데이터인가

| 대상 | 위치 | 비고 |
|---|---|---|
| 소스·문서·Git 기록 | 앱 폴더와 `.git` | 보존 대상 전부 |
| 앱이 실행 중에 만드는 파일 | 없음 | 기본 실행 전후로 원래 폴더와 새 폴더의 `git status --short`가 비어 있었습니다. [실행 확인] 소스에서도 프로젝트 안에 파일을 쓰는 코드를 찾지 못했습니다. [코드 확인] |
| 운영자가 구성하는 조치 기록 DB(SQLite)·자격 보관소 | 운영자가 지정한 프로젝트 밖 위치 | 이 계획의 백업 대상이 아닙니다. 사용하지 않았고 내용은 확인하지 않았습니다. [미확인] |

### 7-2. 백업

1. GitHub로 올리기: `git push origin main:master`. 올린 커밋만 GitHub에 남습니다.
2. 파일 하나로 백업: 앱 폴더에서 `git bundle create <백업 폴더>\keshev.bundle --all`. 프로젝트 밖 폴더에 만듭니다.
3. 백업에 넣지 않는 것: `.env`, 설정 파일, 키·토큰·인증서. 커밋하지 않은 변경은 백업에 들어가지 않으므로 먼저 커밋합니다.

### 7-3. 복원

1. GitHub에서: `git clone https://github.com/WOOJIN-00/woo-keshev.git <새 폴더>` 후 필요한 커밋을 `git checkout`합니다. 이 방법은 이번에 실행하지 않았습니다. [미확인]
2. 번들에서: `git clone <백업 폴더>\keshev.bundle <새 폴더>`. 복원 후 `git checkout --detach <40자리 커밋>`.

### 7-4. 이번에 점검한 백업·복원

프로젝트 밖의 임시 폴더에서 `git bundle create ... --all`, `git bundle verify`, 번들로 `git clone`을 실행했습니다. 검증 결과는 `The bundle records a complete history.`였고, 복원본에서 재현 커밋 `c974014ddd79116a24b5fae9f7300ffbdf002dd7`을 고정했을 때 추적 파일이 59개로 새 폴더 재현본과 같았습니다. [실행 확인]

### 7-5. 제한

- 재현 당시 재현 커밋은 GitHub에 올리지 않은 상태였습니다. 이 커밋과 이 문서의 커밋은 push하기 전까지 GitHub 백업에 없습니다.
- 번들은 같은 PC의 다른 폴더에 만든 사본이면 PC 고장에 대한 백업이 되지 않습니다. 다른 저장 장치나 GitHub에 함께 두어야 합니다.
- 원래 폴더와 그 Git 기록은 이번 재현에서 지우거나 덮어쓰지 않았습니다. 새 폴더는 재현을 위한 사본이며 원본의 대체가 아닙니다.
- 운영자 보관소(자격·조치 기록)의 백업과 복원은 운영자 담당이며 이 계획에 포함하지 않습니다.

## 8. 버전과 지원 범위

**릴리스 상태: 검증 중인 버전입니다. v1.0이 아닙니다.** 기준 버전은 시작 틀 `0.2.11`이고 버전 번호는 바꾸지 않았습니다. 22단계 통과가 있더라도 원문 검토 기준의 수료이며, 실제 운영 인증이나 v1.0 자동 인증이 아닙니다.

실제로 확인한 범위:

- 새 폴더에서 설정 파일 없이 서버가 켜지고, 응답하고, 종료·재실행되는 것
- 연결 없는 기본 실행에서 데이터 API가 `ENGINE_NOT_CONNECTED`로 응답하는 것
- 패키지 조회 API가 `not_configured`로 응답하는 것
- 예제 모드에서 데이터 API와 판정이 `demo`로 응답하는 것
- 학생 함수 8개가 모의 입력과 예제 응답에서 4장의 상태대로 그려지는 것(가짜 DOM)

미해결·누락 사항:
