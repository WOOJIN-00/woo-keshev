# 연결 상태·방화벽 설정·Windows 기록 건수 읽기 (읽기 전용)

이 문서는 학생이 작성했습니다. 제공 문서와 제공 코드(`src/`, `public/`, `tools/`, 제공 `docs/`)는 고치지 않았습니다. 2일차의 `student/pc-status.mjs`와 그 설명서도 그대로 두었습니다.

## 0. 표기와 실행 주체

| 표기 | 뜻 |
|---|---|
| [실제 측정] | 이 PC에서 도구를 실행해 읽은 값입니다. |
| [예시] | 설명용 값입니다. 이 PC에서 읽은 값이 아닙니다. |
| [모의 점검] | 가짜 값으로 함수만 검사한 결과입니다. 이 PC의 실제 값이 아닙니다. |
| [코드 확인] | 소스를 읽고 확인했습니다. 실행하지 않았습니다. |
| [미확인] | 확인하지 못했습니다. 되는 것처럼 읽으면 안 됩니다. |

출력의 **모든 줄 앞에** `[실제 측정]`, `[예시]`, `[모의 점검]` 중 하나가 붙습니다.

**실행 주체:** [실제 측정]과 "실행 확인"으로 적은 항목은 학생의 PC에서 수업용 AI(Claude Code)가 실행하고 출력을 확인한 것입니다. 학생이 직접 같은 순서를 실행한 결과는 7장에 따로 적었고, 직접 확인하지 못한 부분은 [미확인]으로 남겼습니다.

## 1. 제공 기능과 내가 만든 부분

| 구분 | 내용 |
|---|---|
| 제공 기능 | 앱에는 네트워크 구성, 방화벽 설정, Windows 기록 건수를 보여 주는 기능이 없습니다. 「내 기기」는 운영 측이 판정한 보안 기준 충족 여부이고, 「진단 정보」는 요청 식별자·버전·엔진 상태·시각만 담습니다. [코드 확인] |
| 내가 만든 부분 | `student/pc-security-status.mjs`(읽기 도구), `docs/STUDENT_PC_SECURITY_STATUS.md`(이 문서) 두 파일입니다. |
| 앱 화면과의 관계 | 이 도구는 **앱 화면에 나오지 않습니다.** PowerShell에서 실행합니다. 화면에 넣으려면 제공 파일을 고쳐야 해서 하지 않았습니다. |

## 2. 무엇을 어떻게 읽는가 (모두 읽기 명령)

도구는 허용 목록에 있는 읽기 명령만 실행하고, 실행 전에 명령 문자열이 허용 목록 안에 있는지 스스로 검사합니다. 허용 목록 밖의 명령(`Set-`, `New-`, `Remove-`, `Invoke-` 등)이나 `netsh`가 섞이면 실행하지 않습니다. 사용자가 입력한 값은 시간 범위(1~168 정수) 하나뿐이며, 문자열을 명령에 끼워 넣지 않습니다. [코드 확인, 모의 점검]

| 영역 | 읽는 명령 | 보여 주는 값 |
|---|---|---|
| 네트워크 구성 | `Get-NetAdapter`, `Get-NetConnectionProfile` | 어댑터 이름·종류(유선/무선)·물리/가상·연결 상태·링크 속도, 연결 범주(공용/개인/도메인), IPv4·IPv6 연결성 |
| 방화벽 설정 | `Get-NetFirewallProfile` | Domain·Private·Public 프로필의 켜짐 여부, 기본 인바운드·아웃바운드 동작 |
| Windows 기록 | `Get-WinEvent` (System·Application만) | 지정 시간 범위(기본 24시간)의 오류·경고 건수, 항목당 최대 1000건까지 셈 |
| 실행 권한 | .NET 권한 확인 | 일반 권한인지 관리자 권한인지 |
| 앱의 SDP 연결 | 로컬 앱 `GET http://127.0.0.1:포트/api/diagnostics` | 앱의 엔진 상태(미연결/예제 모드/연결 설정됨) |

**읽거나 표시하지 않는 것:** IP 주소, MAC 주소, 무선 이름(SSID), 기록 메시지 본문, Security 기록. 어떤 값도 파일로 저장하지 않습니다. [코드 확인, 모의 점검]

**도구가 하지 않는 것:** 방화벽·보안 설정 변경, 외부로의 접속(인터넷 연결 시험 포함), 포트 검색, 공격이나 침투를 흉내 내는 시험. 로컬 앱(127.0.0.1)의 진단 응답만 읽습니다.

참고로 2일차 도구는 PowerShell을 쓰지 않았지만, 이 도구는 운영체제에 기본으로 있는 `powershell.exe`를 읽기 명령 실행에 씁니다.

## 3. 침해 판정이 아니라는 것

Windows 기록의 오류·경고 건수는 **침해나 공격 탐지 결과가 아닙니다.** 드라이버·서비스·앱이 평소에 남기는 오류와 경고도 포함됩니다. 도구는 이 안내를 건수 아래에 항상 적고, 기록을 읽지 못해 확인 불가일 때도 적습니다. 건수가 0이어도 안전하다는 뜻이 아니고, 많아도 침해라는 뜻이 아닙니다. 도구는 정상·위험·안전 같은 판정을 하지 않습니다.

방화벽의 `NotConfigured`는 "정책으로 지정되지 않음"일 뿐 실제로 적용되는 기본 동작을 알려 주는 값이 아니어서, 원래 값과 함께 그렇게 설명합니다.

## 4. 읽지 못한 값 (확인 불가)

값을 짐작해서 채우지 않고 `확인 불가 — 이유: ...`를 보여 줍니다. 이유에는 오류 이름이나 코드만 쓰고 경로는 넣지 않습니다.

| 상황 | 표시 |
|---|---|
| 관리자 권한이 필요한 항목이라 접근 거부 | 확인 불가와 이유, "관리자 권한이 필요한 항목일 수 있어 바꾸려 하지 않았습니다" |
| 영역 하나가 실패(예: 네트워크만) | 그 영역만 확인 불가, 나머지는 그대로 표시 |
| PowerShell을 실행하지 못함·시간 초과(20초)·결과를 해석할 수 없음 | 세 영역 모두 확인 불가와 이유. SDP 구역은 따로 판정 |
| 어댑터 종류가 유선·무선이 아님 | 유선·무선으로 단정하지 않고 `종류 확인 불가(MediaType=...)` |
| 앱 서버가 꺼져 있거나 포트가 다름 | SDP 상태 확인 불가. **"SDP 미연결"로 쓰지 않음** |

위 처리는 [모의 점검]으로 검사했습니다. 실제 PC에서 접근 거부가 일어나는 것을 재현한 것은 아닙니다. [미확인]

## 5. SDP 연결 상태는 PC 조회와 따로

출력은 두 구역으로 나뉩니다.

- **PC 조회 구역:** 이 PC의 Windows에서 읽은 값. SDP 문구가 들어가지 않습니다. [모의 점검]
- **앱의 SDP 연결 상태 구역:** 앱이 알려 주는 엔진 상태.

| 앱 진단 응답 | 표시 |
|---|---|
| 엔진 `disconnected` | **SDP 미연결** |
| 엔진 `demo` | 예제 모드. 실제 SDP가 아님 |
| 엔진 `connected` | SDP 연결 설정됨. 연결 설정이 켜졌다는 뜻이며 실제 SDP 응답이 성공했다는 확인이 아님 |
| 응답 없음·형식이 다름·알 수 없는 값 | 확인 불가 |

두 구역은 서로 영향을 주지 않으며 하나의 "정상" 표시로 합치지 않습니다.

## 6. 같은 결과를 다시 만드는 순서

작업 폴더는 `student\pc-security-status.mjs`가 보이는 폴더의 최상위입니다. Node.js 24.19.0이 필요하고 `npm install`은 필요 없습니다. **관리자 권한이 아닌 일반 PowerShell 창**에서 실행하세요. 관리자 창에서도 실행은 되지만 일반 권한에서는 확인 불가인 항목까지 읽힐 수 있어 결과가 달라집니다.

```powershell
# 1) 문법과 모의 점검
node --check student\pc-security-status.mjs
node student\pc-security-status.mjs --self-test

# 2) 설명용 예시 값 (실제 값이 아님)
node student\pc-security-status.mjs --example

# 3) 실제 조회 (기본: 최근 24시간, 앱 포트 5189)
node student\pc-security-status.mjs

# 4) 옵션: 시간 범위, 앱 포트
node student\pc-security-status.mjs --hours 1
node student\pc-security-status.mjs --app-port 5999
```

SDP 구역을 확인하려면 앱이 켜져 있어야 합니다. 앱은 다른 PowerShell 창에서 앱 폴더(`on-client`)의 `.\tools\start-alekov.ps1`로 켭니다(앞의 실행 설명서 참고). 앱이 꺼져 있으면 SDP 구역은 "확인 불가"로 나오는 것이 정상입니다.

### 확인 순서와 예상 결과

| 순서 | 할 일 | 예상 결과 |
|---|---|---|
| 1 | `node --check student\pc-security-status.mjs` | 아무것도 출력하지 않고 끝납니다. |
| 2 | `--self-test` | `[모의 점검] 합계: 통과 25, 실패 0` |
| 3 | `--example` | 모든 줄이 `[예시]`로 시작. 네트워크 연결됨, 방화벽 켜짐, 기록 건수와 "침해나 공격 탐지 결과가 아닙니다", `SDP 미연결`이 보이고, Application 경고는 확인 불가 예시로 나옴 |
| 4 | 앱을 켠 상태에서 인수 없이 실행 | 모든 줄이 `[실제 측정]`. **PC 조회 구역**(실행 권한, 네트워크, 방화벽, Windows 기록 + 침해 판정 아님 안내)과 **SDP 구역**(`SDP 미연결`)이 따로 나옴 |
| 5 | 앱을 끈 상태 또는 `--app-port 5999` | PC 조회 구역은 그대로이고 SDP 구역만 `확인 불가 — 이유: 앱 서버가 응답하지 않습니다...`, "확인 불가는 '미연결'이 아닙니다" |
| 6 | `--hours 1` | 기록 시간 범위가 "최근 1시간"으로 바뀜 |
| 7 | `--hours 999` | 사용법이 출력되고 종료 코드 2 |
| 8 | (선택) Windows 도구로 대조 | `Get-NetFirewallProfile`을 직접 실행한 값이 도구의 방화벽 줄과 같아야 함 |

## 8. 한계

- 이 PC 한 대의 Windows만 읽습니다. 다른 PC나 서버는 읽지 않습니다.
- 유선/무선은 어댑터의 `MediaType`으로 구분합니다. 가상 어댑터(VPN 등)는 물리 어댑터와 따로 세어 표시하지만 이름만으로 용도를 알 수는 없습니다.
- 연결성(인터넷 연결 등)은 Windows가 판단한 값입니다. 도구가 외부로 접속해 확인하지 않았습니다.
- 방화벽은 프로필 단위의 켜짐·기본 동작만 읽습니다. 개별 규칙 내용은 읽지 않습니다.
- Windows 기록은 System·Application의 오류·경고 건수만 셉니다. 어떤 이벤트인지, 원인이 무엇인지는 보여 주지 않습니다.
- 앱 화면에는 나오지 않고 PowerShell 도구로만 씁니다.
- 값을 저장하지 않으므로 추이 비교는 하지 않습니다.
