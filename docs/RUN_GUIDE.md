# 신영한(케셰브) 실행 안내서 — 한 장

처음 보는 사람이 이 한 장만 보고 앱을 켜고, 끄고, 막혔을 때 확인하도록 쓴 안내서입니다.
작전: 화면 틀 **관제 대시보드형**(맨 위 상태 카드 4개, 아래 CPU 변화 그래프와 요약) · 포장 **포장 없이 프로젝트 폴더에서 실행**(포장 명령은 실행하지 않음).

표시 규칙: **[AI 확인]** 이 PC에서 AI가 직접 실행해 본 것 · **[직접 확인]** 사용자가 직접 해 보고 알려 준 것 · **[소스 확인]** 파일 내용만 읽었고 실행은 안 한 것 · **[미확인]** 해 보지 않은 것.

**버전 안내(`pc-status-compliant` 브랜치):** 포털 안내문에 따라 제공 서버(`src/server.mjs`) 수정을 되돌렸습니다. 지금 버전의 화면은 PC 값을 읽는 경로를 연결하지 않아 카드·요약이 항상 `확인 불가`로 나옵니다(실측 기능은 제출한 커밋 `ceda9c2`에 있었습니다). 제출한 커밋은 `ceda9c2`이고 재제출은 하지 않았습니다. 이 안내서의 서버 켜기·끄기 절차는 그대로 유효하고, 화면 설명 중 `ceda9c2 기준`이라고 적은 부분은 지금 버전에서 [미확인]입니다.

## 1. 필요한 프로그램

| 프로그램 | 필요한 버전 | 이 PC에서 확인한 값 |
|---|---|---|
| Windows PowerShell 5.1 | 기본 설치 | Windows 11 Pro 10.0.26200에서 사용 [AI 확인] |
| Node.js | `24.19.0` (`package.json`의 `engines`) | `v24.19.0` [AI 확인] |
| 브라우저 | 아무 최신 브라우저 | Chrome에서 화면 확인 [AI 확인] |

- 추가로 설치할 패키지는 없습니다(`npm install` 불필요). `package.json`에 의존 패키지가 없습니다. [소스 확인]
- 시작 도구는 Node.js 22~24만 허용하고, 24.19.0이 아니면 "참고" 한 줄을 보여 줍니다. [소스 확인]
- 인터넷 계정, API 키, 관리자 권한은 필요 없습니다. 이 안내서의 실행은 모두 일반 권한 창에서 했습니다. [AI 확인]

## 2. 폴더 구조와 작업 위치

작업 위치(앱 폴더): `<내 PC의 작업 폴더>\on-client-pcstatus` (브랜치 `pc-status`)

```
on-client-pcstatus\
├─ package.json          시작 틀 이름 alekov-client-starter, Node 24.19.0
├─ src\server.mjs        앱 서버 (127.0.0.1 에서만 열림)
├─ public\               화면 파일(제공)
├─ student\
│   ├─ extension.mjs     관제 대시보드 화면 (내가 만든 부분)
│   ├─ pc-status.mjs     PC 상태(CPU·메모리·디스크) 읽기
│   └─ pc-security-status.mjs  네트워크·방화벽·기록 읽기
├─ tools\start-alekov.ps1  시작 도구
└─ docs\                 설명서 (이 안내서 포함)
```

- 기존 프로젝트 폴더와 `main`은 이 작업에서 바꾸지 않았습니다. [AI 확인]
- 이 폴더가 아니라 다른 폴더의 앱을 켜면 저장된 기록이 다르게 보일 수 있습니다(11장).

## 3. PowerShell 여는 위치

1. 파일 탐색기에서 아래 경로를 주소 표시줄에 붙여 넣고 Enter를 눌러 앱 폴더를 엽니다.
   ```
   <내 PC의 작업 폴더>\on-client-pcstatus
   ```
2. 주소 표시줄에 `powershell`을 입력하고 Enter를 누르면 그 폴더에서 PowerShell이 열립니다. (또는 시작 메뉴에서 PowerShell을 연 뒤 `cd "<내 PC의 작업 폴더>\on-client-pcstatus"`로 이동)
3. 확인: `Get-Location`의 결과가 앱 폴더 경로여야 합니다.

시작 도구는 `tools` 폴더의 상위가 앱 폴더인지 스스로 확인하고, 아니면 안내 문장을 내고 멈춥니다. [소스 확인]

## 4. 실행 명령과 브라우저 주소

```
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

- `-ExecutionPolicy Bypass`는 이 한 번의 실행에만 적용되고 컴퓨터 설정을 바꾸지 않습니다. [소스 확인]
- 포트를 바꾸려면 `-Port 5313`처럼 붙입니다. 이 안내서의 확인은 `-Port 5312`로 했습니다. [AI 확인]
- 같은 앱을 `npm start`(`node src/server.mjs`)로도 켤 수 있습니다. 사용자가 직접 `npm start`로 켜 보니 사이트가 열렸습니다. [직접 확인] 이때 포트는 기본 5189이고, 다른 번호는 `ON_PORT` 환경변수로 정합니다(`$env:ON_PORT = '5313'` 후 `npm start`). `ON_PORT` 방법은 실행해 보지 않았습니다. [소스 확인 / 미확인] AI는 `npm start`를 실행해 보지 않았습니다.

브라우저 주소: **`http://127.0.0.1:5189/`** (기본 포트 5189. `-Port`를 쓰면 그 번호)

## 5. 시작 신호

창에 아래 세 줄이 나오고, 창은 그대로 열려 있어야 합니다(서버가 실행 중). [AI 확인: 포트 5312]

```
케셰브 연결 확인: http://127.0.0.1:5312
케셰브가 켜졌습니다. 브라우저에서 http://127.0.0.1:5312/ 을 여세요.
서버가 응답한 것만 확인했습니다. AI 연결 상태는 화면에서 따로 확인해 주세요.
끄려면 이 창에서 Ctrl+C 를 누르세요.
```

- 주소를 열면 HTTP 200으로 응답했습니다. [AI 확인]
- 서버가 열려 있던 주소는 `127.0.0.1`(이 PC 안에서만)이었습니다. 다른 PC에서 접속되는지는 보지 않았습니다. [AI 확인 / 다른 PC 접속은 미확인]
- 화면의 AI 연결 상태는 이 안내서의 범위 밖입니다. 서버가 응답했다는 것만 확인한 것입니다.

## 6. 끄는 법과 다시 켜는 순서

**끄기**
1. 서버를 켠 PowerShell 창을 클릭하고 **Ctrl+C**를 누릅니다. [직접 확인: 사용자가 이 안내서의 끄는 법대로 껐고 문제 없이 동작]
2. 창을 그냥 닫아도 됩니다. 단, 꺼졌는지는 7장의 ④로 확인합니다.
3. `-Background`로 켰다면 서버 창이 없어서 Ctrl+C를 쓸 수 없습니다. 켤 때 알려 준 프로세스 번호의 `node`를 종료합니다. [직접 확인: 사용자가 `-Background`로 켜고 이 방법으로 껐고 문제 없이 동작]
   1. 켤 때 나온 안내에서 번호를 적어 둡니다. 번호는 켤 때마다 다릅니다.
      ```
      뒤에서 실행 중입니다(프로세스 번호 12345). 끄려면 이 번호의 node 를 작업 관리자에서 종료하세요.
      ```
   2. 번호를 못 적어 뒀다면 7장 ①번 방법으로 5189번을 쓰는 프로그램의 번호(`OwningProcess`)를 찾습니다.
   3. 끄는 방법은 둘 중 하나를 고릅니다.
      - **작업 관리자**: `Ctrl+Shift+Esc` → 왼쪽 **세부 정보** → **PID** 열에서 적어 둔 번호를 찾아 이름이 `node.exe`인지 확인 → 그 줄을 누르고 **작업 끝내기**. 다른 번호의 `node.exe`는 건드리지 않습니다.
      - **PowerShell**: 먼저 `Get-Process -Id 12345`로 이름이 `node`인지 확인한 뒤 `Stop-Process -Id 12345`를 실행합니다(12345 자리에 적어 둔 번호).
   4. 꺼졌는지 확인합니다: `Get-NetTCPConnection -LocalPort 5189 -ErrorAction SilentlyContinue` 결과가 비어 있으면 꺼진 것입니다.

**다시 켜기 (순서대로)**
1. 이전 서버가 꺼졌는지 확인합니다(7장 ④).
2. 3장처럼 앱 폴더에서 PowerShell을 엽니다.
3. 4장의 실행 명령을 실행합니다.
4. 5장의 시작 신호를 확인합니다.
5. 브라우저에서 주소를 엽니다. 새로고침(F5)이 아니라, 코드를 바꿨다면 반드시 서버를 껐다 켠 뒤 엽니다. 서버가 오래된 코드로 계속 떠 있으면 새 화면이 안 나옵니다. [직접 확인: 4일차에 이전 코드 서버를 다시 켜서 새 대시보드가 나옴]

## 7. 막혔을 때 확인 순서

① **"포트 5189 를 다른 프로그램이 쓰고 있습니다"가 나옴**
- 같은 포트로 다시 켜면 아래처럼 나오고 멈춥니다(종료 코드 1). 실제 출력입니다. [AI 확인: 포트 5312]
  ```
  포트 5312 를 다른 프로그램이 쓰고 있습니다. 그 프로그램은 그대로 두고, 다른 번호로 실행해 주세요. 예: -Port 5313
  ```
- 대부분 **서버를 안 끄고 다시 켠 경우**입니다. 먼저 기존 서버 창이 있으면 Ctrl+C로 끕니다.
- **어떤 프로그램이 5189번을 쓰는지 보는 방법** (보기만 하고 아무것도 끄거나 바꾸지 않습니다)

  준비: **PowerShell 창**이어야 합니다. 창의 맨 앞에 `PS C:\...>`처럼 `PS`가 보이면 맞습니다. `C:\...>`만 보이면 명령 프롬프트(cmd)라서 아래 명령이 "내부 또는 외부 명령이 아닙니다"로 실패합니다. 이때는 `powershell`을 입력하고 Enter를 누르면 같은 창이 PowerShell로 바뀝니다.

  1. 서버가 켜져 있는 창은 그대로 두고, **새 PowerShell 창을 하나 더** 엽니다(3장 방법).
  2. 아래 한 줄을 **통째로 복사해서 붙여 넣고** Enter를 누릅니다. 글자를 지우거나 고치지 마세요(끝에 `-` 같은 글자가 남으면 오류가 납니다).
     ```
     Get-NetTCPConnection -LocalPort 5189 -State Listen -ErrorAction SilentlyContinue | Select LocalPort,OwningProcess
     ```
  3. 결과를 읽습니다.
     - **표가 나온 경우** (5189번을 쓰는 프로그램이 있음)
       ```
       LocalPort OwningProcess
       --------- -------------
            5189          5412
       ```
       `OwningProcess` 아래 숫자(예: 5412)를 적어 둡니다. 숫자는 PC마다, 켤 때마다 다릅니다.
     - **아무것도 안 나온 경우** (5189번을 쓰는 프로그램이 없음 = 서버가 꺼진 상태) 이 상태에서 시작 도구를 실행하면 "포트 사용 중" 없이 켜집니다. 4단계는 할 필요가 없습니다. [직접 확인: 사용자 PC에서 서버가 꺼진 상태로 실행]
     - 빨간 오류 "일치하는 MSFT_NetTCPConnection 개체를 찾지 못했습니다"는 `-ErrorAction SilentlyContinue`를 빼먹었거나 글자가 틀렸을 때 나옵니다. 아무것도 안 나온 경우와 같은 뜻이거나 입력 실수이니, 2번 줄을 다시 통째로 복사해서 실행합니다.
  4. 표에서 적어 둔 숫자를 `5412` 자리에 넣어 실행합니다.
     ```
     Get-Process -Id 5412
     ```
     `ProcessName` 칸에 프로그램 이름이 나옵니다.
     - `node`이면 우리 앱(이전에 안 끈 서버)입니다. 서버를 켠 창에서 Ctrl+C로 끄고 다시 켭니다. [AI 확인: 5189번을 `node`가 쓰고 있었음]
     - 다른 이름이면 그 프로그램은 끄지 말고, 아래처럼 다른 포트로 실행합니다.
- 급하면 다른 번호로: `...start-alekov.ps1 -Port 5313` 후 주소도 5313으로 엽니다.
- 포트를 이미 쓰는 프로그램이 있으면 시작 도구는 그 프로그램을 끄지 않고 멈춥니다. 직접 끄거나 다른 포트 번호로 실행하세요. [소스 확인]

② **Node 버전 문제**
- `node --version`으로 확인합니다. 24.19.0이면 맞는 버전입니다. [AI 확인]
- 22~24 밖이면 시작 도구가 "앱은 Node.js 22~24 에서 실행합니다"라며 멈춥니다. Node가 없으면 설치 안내가 나옵니다. 이 두 경우는 실제로 일으켜 보지 않았습니다. [소스 확인 / 미확인]

③ **화면이 예전 모양임**: 서버가 이전 코드로 떠 있는 경우입니다. 끄고 다시 켠 뒤 열고, 그래도 같으면 다른 폴더의 앱이 떠 있지 않은지(주소의 포트) 봅니다.

④ **꺼졌는지 확인**: `Get-NetTCPConnection -LocalPort 5189 -ErrorAction SilentlyContinue` 결과가 비어 있으면 꺼진 것입니다. 포트 5312에서 끈 뒤 이 방법으로 남은 연결 0개, 남은 확인용 `node` 0개를 확인했습니다. [AI 확인]

⑤ **「PC 상태 조회」가 실패함**: 8장과 10장의 실패 화면에 이유와 다음에 할 일이 나옵니다. 서버를 껐다 켜는 것이 첫 번째 시도입니다.

## 8. 읽기 전용이라는 점, SDP는 실제로 연결되지 않는다는 점

- 지금 버전의 화면은 PC 상태·네트워크·방화벽·기록을 읽지 않습니다(읽는 서버 경로를 연결하지 않음). 값은 명령줄 도구 `node student\pc-status.mjs`, `node student\pc-security-status.mjs`로 확인합니다.
- 이 앱의 PC 상태·네트워크·방화벽·기록 조회는 **읽기만** 합니다. 설정을 바꾸거나 보안 조치를 하지 않고, 관리자 권한을 쓰지 않습니다. 읽기 전용 허용 목록에 있는 PowerShell 명령만 거칩니다. [소스 확인 / 점검 도구 자체 점검 통과]
- 화면에 상태를 판정하는 말이나 상태에 따라 바뀌는 색은 없습니다. 숫자와 변화만 보여 줍니다.
- 「Windows 기록」 건수는 "침해나 공격 탐지 결과가 아닙니다."
- **SDP는 실제로 연결하지 않습니다.** 화면의 SDP 칸은 `SDP 미연결`로 표시되며, 조회 중에 SDP 서버에 접속하지 않습니다. 조회가 실패했을 때는 "미연결"이 아니라 `확인 불가`로 씁니다. [소스·설명서 확인 / 화면 표시는 직접 확인한 범위 밖]
- 기록은 이 브라우저의 `localStorage`에만 저장되고(숫자만, 최대 10개), 서버나 외부로 보내지 않습니다. 「기록 지우기」로 지울 수 있습니다.

## 9. 「PC 상태 조회」로 확인할 화면 순서

지금 버전(`pc-status-compliant`)과 제출한 `ceda9c2`는 조회 뒤 화면이 다릅니다.

### 9-1. 지금 버전

1. **조회 전**: 카드 4개(CPU·메모리·디스크·방화벽) 위에 「PC 상태 조회」 버튼이 **한 곳**, 옆에 `조회 전`. 카드는 모두 `조회 전`.
2. **조회 실패**: 버튼을 누르면 `조회 중…` → `14:02 조회 실패`(두 번째부터 `다시 조회 실패`). 카드 4개는 모두 `확인 불가`와 이유 "제공 서버를 고치지 않아 PC 읽기 경로를 연결하지 않았습니다(HTTP 404)"가 나옵니다. 카드에 값과 `[실제 측정]` 표시는 없습니다. (시각 `14:02`는 예시 값입니다.)
3. **요약과 패널**: 한 줄 요약은 `확인 불가`이고, 앱의 SDP 상태는 PC 조회와 따로 읽어 `SDP 미연결`로 나옵니다. 아래 「핵심 3가지」 패널에 「조회하지 못한 항목과 다음에 할 일」이 나옵니다.
4. **「자세히」**: "이 제출 버전은 제공 서버를 고치지 않아 PC 값을 읽는 경로를 연결하지 않았습니다…" 한계 문장이 나옵니다. 이 브라우저에 이전 버전에서 저장한 CPU 기록이 2개 이상 있을 때만 막대 그래프가 그려지고 "그래프의 막대는 이전 버전에서 저장된 기록입니다."가 함께 나옵니다.
5. **값 확인은 명령줄**: `node student\pc-status.mjs`, `node student\pc-security-status.mjs` (PowerShell, 읽기만 함).

### 9-2. `ceda9c2` 버전 (참고)

그 버전은 서버에 PC 읽기 경로가 있어 조회가 성공하면 카드에 값이 나왔습니다: `14:02 조회 성공`, 카드의 큰 숫자와 단위(CPU %, 메모리 %, 디스크 GiB, 방화벽 켜짐/꺼짐)와 `[실제 측정]`, 「CPU 사용률 변화」 막대 그래프와 `직전보다` 한 줄, `네트워크 …` · `Windows 오류 …` 한 줄 요약. 자세한 내용은 `docs/STUDENT_DASHBOARD.md` 10장(`ceda9c2` 기준)입니다.
